# 卡坦岛（Catan）项目总结

> 截至 2026-10-08 · Godot 4.7.2 · 约 5100 行 GDScript · M1 / M2 两个里程碑均已验收通过

---

## 1. 项目是什么

单机人机对战的卡坦岛（基础版规则），1 名人类玩家 + 3 个可配置难度的电脑。
不做联网，架构上为 5–6 人扩展留了接口。

**当前状态：能完整打完一局。** 人类点击棋盘落子，三个 AI 各自按难度行动，
掷骰产出、强盗、发展卡、银行交易、胜负判定全部跑通。

截图必须去掉 `--headless`，否则截不了图。

## 3. 架构

```
表现层    ui/          board_view.gd（棋盘绘制+命中测试）· hud.gd（面板）· palette.gd（配色）
              ↕ 信号
调度层    game/        game_director.gd（交互状态机）· intent_provider.gd（人机共用接口）
              ↕ 方法调用
规则层    core/        9 个脚本，全部 RefCounted，零 Node 依赖
          ai/          evaluation.gd（评分库）· ai_base.gd · 三档难度子类
```

**三条铁律：**

1. **规则层禁止依赖任何 UI / Node。** 这是 AI 平衡性能被批量验证的前提 ——
   一局能在 headless 下 56 毫秒跑完，才能跑 500 局拿统计。
2. **AI 与人类共用 `IntentProvider` 接口。** 加一档难度 = 加一个 `AIController`
   子类，不动调度代码。
3. **所有合法性判断集中在 `core/rules.gd`，且是纯函数。**
   便于 AI 做"假设性推演"。

### 关键改造：控制器可分步驱动

原本 `GameController.run()` 是一次性跑完整局的阻塞循环，没法穿插人类操作。
改造成 `setup_* / begin_turn / apply_action / finish_turn / advance_player`，
再把阻塞式 `run()` 架在这套 API 之上。

**收益：界面和批量验收走的是同一条代码路径。** 不会出现"模拟跑得好好的、
界面上一玩就出问题"。改规则时两边行为必然一致。

## 5. 棋盘几何

**取向选 pointy-top**（尖角朝上），因为这样横排才是经典卡坦岛的 3-4-5-4-3。

拓扑不手写邻接表，而是"算出所有顶点像素坐标 → 取整合并"得到共享的顶点/边，
19/54/72 由几何自动保证。

**实测规模：**

| 指标 | 值 |
|---|---|
| 地块 / 顶点 / 边 | 19 / 54 / 72 |
| 外边界边 / 内部边 | 30 / 42 |
| 顶点按相邻地块数分布 | 挨 1 个：18 · 挨 2 个：12 · 挨 3 个：24 |
| 顶点图连通性 | 54/54 全连通 |

> 顶点度数分布这个数一开始是推错的（按"正六边形边界"推成 6/36/12）。
> 用欧拉公式复核：`n3 - n1 = 6×19 - 2×54 = 6`，实测 24-18=6 ✓，才确认代码对、断言错。

**海岸线取巧**：每个地块按中心等比外扩一圈铺沙色，相邻地块多出的部分会被邻居
的地块色盖住，于是只有岛屿外缘留下沙色 —— 不必计算岛屿轮廓。

**港口**：9 个（4 个通用 3:1 + 5 个指定 2:1），均匀分布在 30 条海岸边的 9 条上，
港口所在边的**两个端点**即为可使用该港口的顶点。

## 6. 验证体系

四个工具，都能在 headless 下跑：

| 工具 | 作用 |
|---|---|
| `verify_topology.gd` | 硬断言 19/54/72 + 度数分布 + 连通性 |
| `test_rules.gd` | 46 项规则单测 |
| `sim_runner.gd` | 批量对局 + AI 平衡统计 + **两条强制不变量** |
| `test_interaction.gd` | 模拟人类点击打完整局（M2 验收） |
| `screenshot.gd` | 真实渲染截图 + 硬检查（贴图加载数、港口明细） |

### 两条强制不变量

每局结束都会校验，500 局零违规：

1. **资源守恒** —— 银行 + 全部玩家手上，每种资源恒为 19 张
2. **状态完整性** —— 无顶点/边被重复占据、无超上限、无负资源

### 最终验收数据（2026-10-08）

**规则单测：46/46 通过**

**批量对局 500 局**（4 人混合，座位轮换）：

| 难度 | 每席胜率 | 平均终局分 | 村/城/路/券 | 平均最长路 |
|---|---|---|---|---|
| 简单 | 8.4% | 5.54 | 2.7 / 0.8 / 8.0 / 2.5 | 4.16 |
| 标准 | 25.0% | 6.78 | 2.9 / 0.9 / 8.9 / 1.9 | 4.73 |
| 困难 | **41.6%** | **7.89** | 2.5 / 1.3 / 9.1 / 1.7 | 4.49 |

4 人局平均线 25%，梯度为 **简单 0.34× · 标准 1.0× · 困难 1.66×**。
平均 24.5 轮结束，无超时，性能 56.4 毫秒/局。

**专项：1 困难 vs 3 标准（400 局）** —— 困难 33.8% vs 标准 22.1%（相对 1.53×）。

> 卡坦岛的骰子随机性极大，4 人局中强手也很难长期占到 50% 以上，
> 这个梯度符合预期，不是"难度没做出来"。

**M2 交互验收** —— 发棋盘/面板信号模拟点击（与真实鼠标同一代码路径）：

```
模拟点击次数   : 8
人类成功建造次数: 10~21（随局面波动）
OK 非法点击被正确忽略
OK 日志全量保留：共 196 条，最早那条仍在
OK 重开一局：棋盘/建筑/资源已重置，第 0 轮，日志延续到 199 条
M2 验收结果：PASS
```

## 7. 踩过的坑（这一节最值钱）

### 7.1 最长道路算法有真 bug ★

原实现把"两条路共享任一顶点"当作连通。但三条路交于同一点时，会算出一条
**几何上不成立**的路：走完第二条后必须原路折返才能接上第三条 —— 那条路被走了两遍。

**正确模型是顶点图上的最长简单路径**（顶点不重复）。修正后同时满足两个官方裁决：
绕一个地块一整圈算 5 段（不是 6），且对手村庄所在顶点不可穿过、但可作为终点。

诊断靠打印邻接表定位，不是靠猜。

### 7.2 AI 疯狂修路不升城

第一版道路评分按"沿线顶点产出"累加，导致路分和城市同量级。
症状非常直观：**人均每局修 12.5 条路却只建 0.9 座城市** ——
城市是全游戏收益最高的建筑（2 分 + 产量翻倍），这个比例明显是反的。

改成按"这条路**新打通**了哪个顶点"定价后：修路降到 8.9 条、城市升到 1.3 座、
困难 AI 胜率从 34.3% 提到 43.0%。

### 7.3 银行交易分支永远不会执行

它被放在"无事可做"的兜底分支里，可 AI 永远有便宜的路可修，
所以这个分支一次都进不去 —— "差一张矿石就能升城"时它选了一条没用的路。

改为**有分数的选项**参与比较，且不把"修路"算作交易目标（为 2 张资源的路付 4:1 汇率是亏的）。

### 7.4 AI 把自己卡死

3.3 修好后仍出现：白方手握 **16 张木材**、其余四种全 0。
根因是交易只认"这一换立刻能建成东西"，而单次交易永远无法让它立刻可建。

补了**富余转化**规则：某资源严重富余、且换进来的正是所缺时，即使不能立刻建成也允许换。

### 7.5 高亮只判合法，没判买得起

`Rules.valid_settlement_vertices` 只判规则合法性。直接拿来当高亮，
玩家会看到满屏可点位置，点下去毫无反应。必须再叠一层资源检查。

### 7.6 点选模式一次只能选一种

想点路就点不到村庄。补了 `Pick.ANY`：顶点和边都参与命中，按离鼠标更近的判定。

### 7.7 高亮配色试错两轮

- **绿色** → 地形里森林、牧场本身就是绿的，几乎看不见
- **白色** → 四个玩家里"白方"的棋子就是白色的，棋子和高亮分不清
- 最终用**青色 + 深色描边** —— 六种地形色和四个玩家色里都不出现

### 7.8 贴图 UV 坐标系混用 ★

素材是白底方形插画，靠 `draw_polygon` 带 UV 按六边形裁切解决（不需要透明通道）。
但 UV 圆心一开始用了 `BoardTopology.hex_center`（**世界坐标**），
去减 `_p()` 换算后的**像素坐标**顶点 —— 差值巨大导致 UV 越界，
采样全落在贴图白边上，渲染出**一片发白的纯色**。

**最坑的是：它和原本的纯色地块几乎一模一样，肉眼看不出贴图没生效。**

改成从多边形自身算包围盒中心。教训：贴图是否生效必须靠数据验证 ——
已在 `screenshot.gd` 里加了硬检查 `地形贴图: N/6 已加载`，还加了放大参数看细节。

### 7.9 事件日志被截断

原本只显示最近 40 条。改为全量保留 + 滚动条 + 实时条数，
且**只在玩家本来就停在底部时才自动滚动**，否则他往上翻历史会被不断拽回底部。

### 7.10 数组引用自己比自己

判断"日志有没有新内容"时写了 `lines.size() == _log_lines.size()`，
但传进来的就是 `GameState.log_lines` 这个引用，比较长度永远相等 —— 日志再也不更新。
改用「条数 + 末行文本」判断。

### 7.11 自检太死导致误报

`Board.self_check()` 要求强盗必须在沙漠上，但开局后玩家会正常移动它。
拆成参数 `self_check(check_robber)`，只在刚生成时校验这条。

### 7.12 技能文档里的过时结论

`godot-scene-cli` 技能写着"Godot 默认字体不含中文，中文会变豆腐块"。
实测（写探针脚本截图验证）发现 **Godot 4.7 默认字体带系统回退，macOS 上中文完全正常**。
但 `_draw()` 里走 `ThemeDB.fallback_font` 那条路可能拿不到 CJK 字形，
所以棋盘绘制单独造了 `SystemFont`。这条修正已写回技能文档。

> 附带修正：Godot 默认主题是暗色、Label 字接近白色。铺白底验证时不显式设黑字，
> 文字会"隐形"，看起来像根本没渲染 —— 我为此白查了一轮。

## 8. 界面交互

### 操作方式

不需要先点"建村庄"再选位置，**直接点棋盘上的青色高亮**：

- 点顶点 = 建村庄 / 升级城市
- 点边 = 修路
- 掷出 7 时点地块 = 放强盗
- 右侧按钮：结束回合 / 买发展卡 / 银行交易（一键换）/ 打出发展卡 / 重开一局

### 玩家编号

人类是「你」，三个电脑是**电脑A / 电脑B / 电脑C**。

> 原本按难度命名（"电脑·简单"），但三个电脑里有两个同难度时标签完全一样，
> 玩家根本分不清刚才是谁动的。难度信息移到状态栏（"电脑B（标准）行动中…"）
> 和面板行悬停提示。

### 事件日志

**全量保留，不做截断**，面板标题显示总条数（`事件日志（共 196 条）`），带滚动条。
日志只增不减 —— **重开一局时也延续**，只在其间加一条「新开一局」分隔。
数据层上限（20000）只是内存兜底，单局几百条永远碰不到。

### 地形图例

左上角，六种地形各一个**小六边形**色卡（用六边形而非方块，和棋盘地块形状一致，
扫一眼就能对色），每行给出地形名与产出资源。棋盘为此右移 60px 腾出空间。

### 重开一局

标题行右侧，**两次确认**（第一次变"确认重开?"并变红，3 秒内再点才生效）。
种子不变，所以重开是同一张棋盘，方便复盘练习。

## 9. AI 设计

三档共用一套评分库（`evaluation.gd`），**差异来自决策质量而非数值大小**：

| 参数 | 简单 | 标准 | 困难 |
|---|---|---|---|
| 评分噪声 | 28 | 7 | 0 |
| 升城倾向 | 0.75 | 1.05 | 1.30 |
| 修路倾向 | 0.8 | 1.0 | 1.10 |
| 针对性(savvy) | 0.2 | 0.55 | 1.0 |
| 交易风险容忍 | 0.6 | 1.6 | 2.6 |
| 随机接受交易 | 35% | 0 | 0 |
| 额外能力 | — | — | 阻断对手、主动交易套利、精准打击领先者 |

**顶点价值** = Σ(pip值 × 资源权重) + 资源多样性加成 + 港口加成。
资源权重随阶段变化（开局木材砖块值钱铺路，中后期麦子矿石值钱升城）。

**AI 参考的公开研究结论**：最长路是最常见制胜路径（占 56~61% 胜局）；
第 3 座村庄建成时间与胜负相关性最强；麦子全程最关键。

**初局布置**额外惩罚"撞重复数字"和"两村共用同一地块"，并优先补足缺失资源种类。

## 10. 已知限制 / 后续可做

| 项 | 现状 |
|---|---|
| **玩家间交易** | **AI 提议自动拒绝**，人类无法主动提议。银行交易可用所以不至于卡死，但缺少卡坦岛最核心的社交层 |
| 弃牌选择 | 掷 7 时自动按"弃最多的"处理，玩家不能自己选 |
| 垄断卡 / 丰收年 | 自动挑最优资源，玩家不能指定 |
| 偷牌对象 | 自动选手牌最多的，可接受但没让玩家选 |
| 动画音效 | 无 |
| 教程 / 存档 / 结算页 | 无 |
| 设置页 | 无（人数、难度、种子目前靠改 inspector 参数） |
| 5–6 人扩展 | 架构预留，未实现 |

### 优先级建议

1. **玩家间交易 UI** —— 体验上最明显的缺口
2. 弃牌 / 垄断 / 丰收年让玩家自己选
3. 设置页（人数、难度、棋盘种子）+ 胜负结算页
4. 动画音效、教程
