## 一、需求原文与拆解

> 骑士卡可以在**摇骰子之前或者之后**打出，所以要有 2 个按钮「掷骰子」和「打发展卡」，如果没有骑士卡则自动掷骰子。打发展卡会触发弹窗，选择当前卡片打出——「骑士」触发地图选择强盗；「垄断」触发弹窗选择玩家拥有的资源（×总数）；「丰收」触发弹窗选择任意 2 张资源（可以相同，两列选择）拿走。

拆解成 7 条可验收项：

| # | 需求 | 类型 |
|---|---|---|
| 1 | 回合开始拆出「掷骰前」阶段，骑士可在掷骰前打出 | 状态机 |
| 2 | 掷骰前出现「掷骰子」「打发展卡」两个按钮 | HUD |
| 3 | 手上没有骑士卡 → 不弹按钮，直接自动掷骰 | 状态机 |
| 4 | 「打发展卡」→ 弹窗列出可打卡片 | HUD 弹窗 |
| 5 | 骑士 → 关弹窗，进入地图选强盗 | 已有链路，接入即可 |
| 6 | 垄断 → 弹窗选 1 种资源，显示场上合计 ×N | HUD 弹窗 |
| 7 | 丰收 → 弹窗两列各选 1 张，允许相同 | HUD 弹窗 |

## 二、现状梳理（改动前的事实）

**回合起点是一步到位的**：`GameController.begin_turn()` 里重置标记 → `on_turn_start` → 立刻掷骰 → 7 触发弃牌+`pending_robber`，否则 `_produce()`。**人类玩家根本不存在"掷骰前"这个时机**，骑士只能掷骰后打。

**发展卡参数现在是 GameDirector 代选的**（`_on_play_dev`）：垄断用 `_best_monopoly_resource()`、丰收用 `_two_most_needed()`。玩家没有选择权——这正是本次要改掉的部分。

**HUD 的发展卡区是一排按钮**（`_dev_grid` + `_refresh_dev`），点一下直接打，没有弹窗。

**骑士链路其实是通的**：`_play_dev_card` → `pending_robber = true` → `_after_human_action` → `ROBBER_HUMAN` → `_on_hex_clicked` → `place_robber`。缺的只是"掷骰前"这个入口，以及放完强盗后要回到哪。

**关键字段现状**：

| 字段 | 现状 | 够不够用 |
|---|---|---|
| `st.dice` | 初始 0，但**上一回合的值会残留** | ✗ 不能用 `dice == 0` 判断"还没掷"，需新增标记 |
| `st.dev_played_this_turn` | 已有，每回合限 1 张 | ✓ |
| `st.pending_robber` | 已有 | ✓ |
| `p.dev_cards` / `p.fresh_dev_cards` | 当回合买的卡在 fresh 里，`finish_turn` 才并入 | ✓ 天然满足"当回合买的卡不能打" |

**`begin_turn` 的调用方只有两处**（影响面小）：`GameDirector._begin_next_turn()`、`GameController._auto_turn()`（无人值守/AI）。

## 三、改动设计

### 3.1 状态机：新增 `S.HUMAN_PREROLL`

```
GameDirector.S：SETUP_HUMAN → SETUP_AI → ROBBER_HUMAN → ROBBER_AI
                → HUMAN_PREROLL（新）→ HUMAN_TURN → AI_TURN → GAME_OVER
```

| 状态 | 允许的操作 |
|---|---|
| `HUMAN_PREROLL` | 点「掷骰子」/「打发展卡」（弹窗里**只列骑士**）；**不能建造、不能结束回合** |
| `HUMAN_TURN` | 建造 / 交易 / 打发展卡（全部可打类型）/ 结束回合 |
| `ROBBER_HUMAN` | 点地块放强盗（沿用现有） |

配套：`_update_highlights` 在 `HUMAN_PREROLL` 下 `set_pick_mode(Pick.NONE)`；`refresh()` 的 `can_act` 判定要把 `HUMAN_PREROLL` 算进去。

### 3.2 GameController：拆 `begin_turn` 为两步（AI 行为不变）

| 新增/改动 | 内容 |
|---|---|
| `start_turn(pid)` | 重置 `dev_played_this_turn` / `free_roads_remaining` / `turn_actions_done` / `dice_rolled=false` + `on_turn_start` + 日志「【X】回合开始」 |
| `roll_dice(pid)` | 原掷骰逻辑原样搬过来：两颗骰子 → `st.dice` → 日志 → 7 走 `_handle_seven_discards` + `pending_robber=true`，否则 `_produce()`；最后 `dice_rolled = true` |
| `begin_turn(pid)` | **= `start_turn` + `roll_dice`**，给 AI / `run()` / `sim_runner` 用，**行为与改动前完全一致** |

⚠️ **验收点**：RNG 调用顺序必须一字不差（两颗骰子仍在同一步取），否则 `sim_runner` 的胜率矩阵会和改动前对不上——这是"拆分没拆坏"的判据。

### 3.3 GameState：新增 `dice_rolled: bool`

不能用 `st.dice == 0` 判断（上一回合的值会残留）。`start_turn` 置 false，`roll_dice` 置 true，`begin_turn` 里顺带置 true。

### 3.4 GameDirector：接线与流转

| 环节 | 改动 |
|---|---|
| `_begin_next_turn` | `check_win` → `ctl.start_turn()` → **若 AI，或人类无骑士可打** → `ctl.roll_dice()` 再按 `pending_robber` 分支；**否则** → `_set_state(S.HUMAN_PREROLL)` |
| 新信号 `roll_dice_pressed` | 仅 `HUMAN_PREROLL` 响应 → `roll_dice()` → 有 `pending_robber` 走强盗，否则 `_enter_main_phase()` |
| 打骑士（掷骰前） | `apply_action` → `pending_robber` → `_enter_robber_phase()` |
| **`_on_hex_clicked`** | **最容易漏**：放完强盗后现在固定 `_enter_main_phase()`。必须改成 —— `dice_rolled ? main : HUMAN_PREROLL`，否则掷骰前打骑士会被误推进到主阶段，本回合骰子永远掷不出来 |
| `_on_play_dev` | 改成接收 UI 传来的参数（见 3.5），删掉 `_best_monopoly_resource` / `_two_most_needed` 的代选逻辑（丰收/垄断改由玩家指定；AI 分支不受影响，AI 仍在 `ai_base.gd` 里自己选） |

### 3.5 HUD：两个按钮 + 三级弹窗

**按钮**（动作行 `结束回合 / 买发展卡 / 兑换` 基础上）：

| 按钮 | 可用条件 |
|---|---|
| 掷骰子 | 仅 `HUMAN_PREROLL`（其余状态隐藏或置灰） |
| 打发展卡 | 未打过卡 且 有可打卡；`PREROLL` 时弹窗只列骑士，`HUMAN_TURN` 时列全部 |

原来「发展卡」那一区（`_dev_title` + `_dev_grid`）**删掉**，功能并入弹窗。

**弹窗结构**（沿用银行兑换弹窗的 `_card_style` / `_res_button` / 居中套路）：

```
打发展卡 → 选卡弹窗
           ├ 骑士     → 直接打出 → 地图选强盗
           ├ 修路     → 直接打出（free_roads_remaining += 2）
           ├ 垄断     → 资源弹窗（单列 5 项，文案「木 ×7」）→ 打出
           └ 丰收年   → 资源弹窗（左右两列各 5 项，可相同）→ 打出
```

- **垄断**：单列，每项显示除自己外全场合计 `×N`（tooltip 里按对手拆分）。`N == 0` 时禁用（避免 0 收益的空操作）
- **丰收**：左右两列各 5 项，**允许两列选同一资源**；银行库存为 0 时禁用；两列选同一资源时要求银行 ≥ 2 张（否则第二张发不出来，UI 上直接禁掉并说明）
- 两列都选完「确定」才可点，与银行兑换弹窗一致

**信号**：新增 `roll_dice_pressed`；发展卡统一用一个带参信号 `dev_card_played(card: int, r: int, r1: int, r2: int)`（无参卡片填 -1），替代现在的 `play_dev_pressed(card: int)`。保持"HUD 只显示+发信号，判断全在 Director"的契约（AGENTS.md 架构契约 6）。

### 3.6 规则边界清单（逐条要验）

| 边界 | 期望 |
|---|---|
| 每回合最多 1 张 | `dev_played_this_turn` 兜住；掷骰前打了骑士，掷骰后不能再打 |
| 当回合买的卡不能打 | 卡在 `fresh_dev_cards`，`finish_turn` 才并入；`playable_dev_cards` 已排除 |
| 胜利点卡 | 自动计分，弹窗里不出现 |
| 掷骰前打骑士后 | 仍要掷骰（回 `HUMAN_PREROLL`），且强盗必须先放完 |
| 掷出 7 与骑士的强盗 | 两条路径都进 `ROBBER_HUMAN`，放完强盗的去向不同（7 → main，骑士 pre-roll → PREROLL） |
| 垄断 0 张 / 丰收银行不足 | 按钮禁用或提示，不产生空操作 |
| 骑士与最大军队 | `_update_largest_army()` 已在 `_play_dev_card` 里调用，无需改 |

## 六、风险与取舍

1. **垄断显示合计会暴露对手手牌**：单机人机可接受，且用户明确要求「×总数」；若不希望泄露，`N` 可改成不显示（待确认）。tooltip 里按对手拆分是额外的信息量，同样可关。
2. **`test_interaction.gd` 会卡死**：它用发信号的方式模拟真人，新增 PREROLL 后，若人类手上有骑士，它会停在等掷骰而没人掷 → 整局走不完。改造方式：在 `_try_human_build` 之前补一步「若处于 PREROLL 则 `hud.roll_dice_pressed.emit()`」。`screenshot.gd -- auto`（人类交给 AI）不受影响。
3. **不能用 `st.dice == 0` 判断未掷骰**（值会残留），必须加 `dice_rolled`。
4. **PREROLL 下要禁建造**：`set_pick_mode(Pick.NONE)`，否则玩家能在掷骰前偷建。
5. **弹窗套弹窗的层级**：选卡 → 垄断/丰收 是二级弹窗，取消要能退回一级；建议一级弹窗在二级打开时保持可见（二级关闭后回到一级），避免"取消后整个流程消失"的迷惑。
