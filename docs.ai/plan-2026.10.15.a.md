## 2. 先拍板：7 个设计决定

| # | 决定 | 理由 |
|---|---|---|
| **D1** | **`Layout` 只承载"竖屏分支的算式 + 朝向状态 + 常数"；横屏算式原地不动**（`BoardView.board_origin_for` / `HUD.content_rect` / `_apply_layout` 的横屏路径逐字节保留），两个入口各加一个三元分支 | 这两个静态函数是 `test_safe_area` / `test_legend` 的"真代码"入口；搬进 `Layout` 再改测试 = 白扩大桌面基线的回归面。分支点总共 3 处、每处一行，竖屏算式集中在 `Layout` —— b §4.1 的意图（不让 `if portrait` 散落）仍成立 |
| **D2** | 朝向判定拆成纯函数 `is_portrait_for_window(win: Vector2i) -> bool`，`is_portrait()` 只回读**锁定值** | 纯函数可在 headless 里钉死三种启动方式（P0 探针已实测）；`_ready` 里只剩两句话 |
| **D3** | `px_per_unit` **只在竖屏分支被写回**，横屏永不覆写，也不引入 `-1` 哨兵 | b M1/R2：`test_ports` / `shot_help` / `screenshot` 全在读写这个成员，必须单一真源 |
| **D4** | 竖屏 **不叠加** `BOARD_X_BIAS`（它是"给左上角按钮腾地方"的横屏补偿） | b §3.2 |
| **D5** | 写 `content_scale_size` 前先比现值，**不同才写** | 少一次无谓 `size_changed` → 全屏重排；"桌面启动零副作用"更硬 |
| **D6** | 日志弹窗在 Esc 链里紧跟 `_dlg`（第二层），且用 `null` 守卫 | 重开弹窗是全屏遮罩，打开时点不到面板按钮，两者不会真叠；守卫保证桌面（无此弹窗）零分支 |
| **D7** | 横屏与竖屏的日志形态**不同构**：横屏保持内嵌（今天的样子），竖屏才换成按钮 + 弹窗 | 见 §3.1 的 N2 —— 这是"桌面逐像素不变"红线的直接推论，不是偷懒 |

### 4.1 新增 `ui/layout.gd`（`class_name Layout`，`extends RefCounted`，全静态）

| 成员 | 值 / 返回 | 说明 |
|---|---|---|
| `set_portrait(v)` / `is_portrait()` | 锁定值，默认 `false` | 唯一判定入口；测试注入用（同 `SafeArea.set_override` 模式） |
| `is_portrait_for_window(win: Vector2i)` | `win.x > 0 and win.x < win.y` | 纯函数。headless 是 0×0 → `false`；`(1280,720)→false`、`(720,1280)/(1080,2400)/(1536,2048)→true` |
| `content_scale_for(portrait)` | `1280×720` / `720×1280` | 启动时一次性设置 |
| `BOARD_W_U / BOARD_H_U` | `9.9003 / 9.2400` | 19 格外接矩形 + 海岸带 + 港口牌外推（b §3.1） |
| `FIT / PAD / GAP` | `0.98 / 8.0 / 12.0` | |
| `UI_RATIO / UI_MIN / UI_MAX` | `0.48 / 400.0 / 940.0` | 先按 b §3.2，P2 出图后校正（§6 Q4） |
| `ui_height(vp)` | `clampf(vp.y * UI_RATIO, UI_MIN, UI_MAX)` | |
| `board_rect(vp, ins)` | 竖屏：`Rect2(ins.x+PAD, ins.y+PAD, vp.x-ins.x-ins.z-2*PAD, avail_y-ui_h-PAD-GAP)`，`avail_y = vp.y-ins.y-ins.w` | **只在竖屏调用** |
| `px_per_unit_for(bz)` | `minf(bz.w/9.9003, bz.h/9.2400) * 0.98` | **只在竖屏调用**（D3） |
| `panel_rect(vp, ins)` | 竖屏：`Rect2(0, board_rect.end.y + GAP, vp.x, vp.y - board_rect.end.y - GAP)` | 底色铺到屏边，安全区只作用于内容 |
| `content_rect(vp, ins)` | 竖屏：`Rect2(ins.x+14, panel.y+10, vp.x-ins.x-ins.z-28, panel.h-20-ins.w)` | 保证内容不越安全区 |

**算式自检**（与 b §3.3 逐列对齐，`test_layout.gd` 直接断言）：

| 机型 | vp | ins | `ui_height` | board_rect | `px_per_unit` |
|---|---|---|---|---|---|
| 1080×2400 | 720×1600 | (18,34,18,18) | 768 | (26, 42, 668, 760) | **66.12** |
| 1080×1920 | 720×1280 | (18,34,18,18) | 614.4 | (26, 42, 668, 593.6) | **62.96** |
| iPad 3:4 | 720×960 | (18,34,18,18) | 460.8 | (26, 42, 668, 427.2) | **45.3**（能跑不崩即可） |

### 4.4 开工第一步：把 b §8 留的"另一半"量掉（先量后写，别推理）

P0 量到"`_ready` 那刻视口没就绪"；P1 要量的是：**写 `content_scale_size` 之后，`size_changed` 在第几帧触发、新 vp 第几帧生效**。做法：给 `tools/probe_display.gd` 加一个"等帧后设基准再连测 3 帧 vp"的分支（或临时脚本），跑 `--resolution 720x1280` 记下帧号，写进本文档回填。这条直接决定 `shot_portrait.gd` 要等几帧（§5.2）。

> **实测回填（2026-10-17，`probe_display.gd -- css`，Windows / 4.7.2）**：写入 `720×1280` 后
> `size_changed` 在**同一帧内**触发，且触发时新 vp 已经生效（探针在第一个 awaited
> `process_frame` 之前已读到新 vp）。即：`BoardView._ready` 写基准后**无需额外等帧**，下一个
> `process_frame` 即可安全读 vp；`shot_portrait.gd` 等 20 帧（沿用 shot_help 的量级）绰绰有余。
> 另实测：本机 `--resolution 720x1280` 实际窗口 720×**1061**（屏幕高度限制），expand 短边对齐
> 得 vp 868×1280（仍竖屏）。推论：竖窗口下"窗口 ≠ 基准"，合成鼠标坐标必须乘 `窗口/视口` 倍率
> （trap 3 的推论，已写成 AGENTS.md trap 18，`shot_portrait.gd` 按此实现）。
